# PYNQ DMA 与 Overlay 排障流程

1. 先核对 bit/hwh、驱动和寄存器契约的版本与哈希，再连接设备。不要只替换 bit。
2. 确认没有第二个进程持有摄像头或 DMA。先调用应用正常停止入口，再等待传输排空；确认通道停下后才释放物理缓冲区。
3. 检查帧地址、步长、有效区域和帧完成标记。采集帧与标注帧分别持有，只有完成的帧才能发布给显示或推理。
4. 按所用驱动准备接收端再启动发送端，记录超时前后状态。不要循环盲写复位位或在运行中探测未知外设地址。
5. 在持有硬件的主线程中统一访问 MMIO。网页线程只提交已校验命令。
6. 对不可取消的推理用代次编号隔离旧结果。切换任务时清空确认窗口，并拒绝旧代次结果。
7. 部署先备份再替换，数据目录保留 UID/GID，检查日志重定向权限。运行代码的用户与创建日志的 shell 都必须有权限。
8. 冷启动能跑而热更新失败时，先保存差异和原始报错。不要据此断言硬件拓扑错误；本项目的热启动原因尚未定位。

失效条件：本流程不提供通用寄存器地址、任意板卡的复位顺序或特定缓存一致性保证；流接口、物理内存或驱动不同必须重新核对。硬件错误、模型误判和网络延迟需分别定位。
